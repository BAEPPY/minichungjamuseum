# 우리들의 청자박물관 · 탐험 게임

화면 전체의 등각 맵에서 픽셀 아바타를 움직이며 관찰하고 보고서를 전시하는 **개인 탐험 웹게임**입니다. 입장 마당, 세 나라 도자기 비교관, 고려청자 탐구관, 보고서 책상과 야외 전시 마당이 하나의 공간에 있습니다. 설명·3D 관찰·글쓰기는 게임 위의 창으로 열립니다.

맵은 JavaScript + Canvas 2D, 확대 관찰은 Three.js(WebGL)로 구현했습니다. 건물·바닥·가구·식물·캐릭터는 개별 제작한 PNG를 사용하며 [자산 목록](public/art/README.md)에 기록합니다. GitHub 저장소를 Vercel에 연결해 배포하며 **Sites는 사용하지 않습니다.**

## 실행

Node.js 22.12 이상 또는 24 LTS를 권장합니다.

```sh
npm ci
npm run dev
```

`http://localhost:5173`에서 실행합니다. 배포 빌드는 `npm run build`, 결과 폴더는 `dist`입니다.

## 게임 조작

- 방향키 / WASD: 화면 방향으로 캐릭터 이동
- 바닥 클릭·터치: 진열대를 피해 해당 위치로 이동
- 전시물 클릭: 가까이 걸어가기. 가까운 전시물은 다시 클릭해 관찰
- **F 키 / 화면 상호작용 버튼**: 관찰·비교 기록·보고서·전시 창 열기
- 모바일·태블릿: 화면 방향 버튼과 상호작용 버튼 사용
- 지도: 장소 가까이 이동. 입장·비교·퇴장 단계의 조건은 유지
- 수첩: 작품별 사진·메모 확인, 비교 기록과 보고서 이어 쓰기
- 캐릭터: 닉네임, 탐험복 색 3개, 머리 모양 2개 중 선택
- 맵 확대·축소: 카메라 배율 조절. 카메라는 캐릭터를 따라감

## 수업 코스

**입장 → 세 나라 도자기 3점 비교·근거 기록 → 고려청자 5점 탐구 → 통합 보고서 → 퇴장·전시** 순서입니다. 기존 제작 영상관과 MP4 시청 단계는 제거했습니다.

1. 닉네임과 간단한 아바타를 선택하고 입구에서 입장합니다. 이용약관·연령 확인 줄은 표시하지 않습니다.
2. 왼쪽 비교관의 일본·중국·고려 작품을 각각 관찰합니다. 회전·확대해 특징을 한 줄씩 적고, 중요한 부분은 사진으로 담습니다.
3. 비교 책상에서 **고려청자의 뛰어나다고 생각하는 점**과 **다른 두 작품과 비교해 직접 본 근거**를 적습니다. 세 작품의 관찰·특징 기록과 생각·근거를 모두 채우면 다음 탐구가 열립니다.
4. 오른쪽 고려청자 5점을 각각 관찰하고 특징을 한 줄씩 기록합니다. 비교관에서 상감 매병을 보았더라도 탐구관의 방문 기록은 별도로 쌓입니다.
5. 보고서 책상에서 이름·제목·대표 청자를 정하고, 앞의 3점 비교 기록과 5점 특징을 **하나의 보고서**로 정리합니다. 두 활동에서 촬영한 사진 중 보고서에 넣을 1~3장을 고릅니다.
6. 비교 기록·5점 관찰과 특징·보고서 완성을 확인한 뒤 출구로 나갑니다. 보고서 작성만으로 게시되지는 않습니다.
7. 야외 전시대에서 **내 보고서 전시하기**를 누릅니다. 전시판에 다가가 F 또는 화면 버튼으로 다른 보고서를 읽습니다.

사진은 작품별 최대 3장, 최종 보고서는 모든 관찰 사진 중 최대 3장입니다. 비교 내용과 특징을 수정하면 아직 게시하지 않은 보고서의 완료 상태도 다시 확인합니다. 진행 단계·위치·관찰 기록·작성 중 보고서는 이 브라우저의 IndexedDB에 저장됩니다. 이전 코스의 사진·메모·보고서는 보존하지만, 옛 영상 시청 완료가 새 비교 활동을 자동 완료하지는 않습니다.

전시판은 한 번에 6개이며 ‘다음 전시판’으로 다음 묶음을 읽습니다. 새로고침은 첫 묶음으로 돌아갑니다. 브라우저 저장 공간을 삭제하면 로컬 기록도 사라질 수 있습니다.

일본 매병은 공식 뷰어가 사용하는 **6행 × 9열 원본 JPEG 54장**을 `public/models/japan-peony/`에서 직접 제공합니다. 공식 ‘3D Viewer’는 사진 시점을 전환하는 자료로, 3D 메시나 실측 GLB가 아닙니다. 자체 사진 뷰어에서 드래그·방향키로 시점을 바꾸고 확대·촬영하며 비교 기록과 통합 보고서에 사용할 수 있습니다. 외부 iframe이나 임의 재현 모델은 사용하지 않습니다. 작품 목록은 `src/comparison-artifacts.js`에서 관리합니다.

파일은 재인코딩하지 않았으며 원본 URL·크기·SHA-256을 `public/models/japan-peony/source-provenance.json`에 기록합니다. 국립중앙박물관의 원본 자료 이용 조건을 따르며 이 저장소가 새로운 이용허락을 부여하지 않습니다.

관찰 사진과 목록은 GitHub 저장소에 포함되어 Vercel에서 함께 제공합니다. 수업 중 박물관 서버에서 사진을 다시 가져오지 않습니다. 맵에서는 `public/art/previews/japan-peony-cutout.png`의 투명 미리보기로 전시대에 놓인 모습을 표시합니다. 이 지도용 파생 이미지는 원본 `2_4.jpg`를 이미지 편집 도구로 배경 제거한 자료이며, 관찰·보고서 촬영에는 원본 사진을 사용합니다.

색과 윤기는 촬영·조명·모델 표현에 따라 달라질 수 있습니다. 비교 기록은 렌더링의 밝기만으로 우열을 정하기보다 모양, 문양, 장식 방법을 관찰한 근거로 설명하도록 구성했습니다.

## 교사용 3D 자료 등록

설정 → **교사용 · 3D 자료 등록**에서 비교관 3점 또는 탐구관 5점 중 하나를 고르고, 이미지·형상이 함께 들어 있는 **30MB 이하 단일 GLB**를 등록합니다. 형상을 읽을 수 있는지 확인한 뒤 이 브라우저의 IndexedDB에 저장하고 미리보기·관찰·촬영 자료를 교체합니다. 새로고침 후에도 유지되며, 잘못된 새 파일은 기존 자료를 바꾸지 않습니다. ‘등록한 파일 지우기’로 기본 자료로 돌아갑니다. 비교관과 탐구관의 기록 ID는 구분됩니다.

등록 파일은 **해당 브라우저에서만 사용**하며 다른 학생 기기로 자동 배포되지 않습니다. 학급 기본 자료로 제공하려면 GLB를 `public/models/`에 넣고, 탐구관은 `src/artifacts.js`, 비교관은 `src/comparison-artifacts.js`에서 연결해 GitHub/Vercel로 배포합니다. 뷰어 HTML 주소 자체는 GLB 파일이 아닙니다.

베개에 로컬 GLB를 등록하면 일반 자체 3D 뷰어로 바뀌고, 삭제하면 원래의 사진·3D 전환 모드로 돌아갑니다. 기존에 실제 등록 자료로 관찰한 기록과 사진·메모는 파일 교체 때문에 지우지 않습니다.

## 투각 의자 · 제공 WRL 형상과 정점색

사용자가 올린 `image_2026-11-01.zip`의 `청자투각죽문걸상(3000740).wrl`을 직접 변환합니다. **388,424개 정점과 777,108개 삼각형을 유지**하며, 사진을 보고 다시 만든 절차적 형상으로 대체하지 않습니다. 굽이 아래를 향하도록 X축으로 180° 회전하고, 게임 표시 크기만 정규화합니다. 물리 단위나 외부 소장품 식별이 확인된 실측 스캔이라고 주장하지 않습니다.

배포 파일은 `public/models/celadon-stool-wrl.glb`, 변환·출처 기록은 `public/models/celadon-stool-wrl-source.json`입니다. 원본 RGB 정점색을 웹의 선형 색공간으로 변환해 사용합니다. 원본의 색공간 표시는 명시되어 있지 않아 선택한 해석을 기록합니다. 파일이 참조하는 `CDI_DUK05429_1.jpg`는 ZIP에 없으며, 임의 사진 질감으로 대신 채우지 않습니다. 웹용 도자기 광택은 기본 PBR 재질로 표현한 값으로 실제 반사율 측정 자료가 아닙니다.

변환에는 Python 3와 NumPy를 사용합니다.

```sh
python scripts/convert_stool_wrl.py \
  --wrl '/path/to/청자투각죽문걸상(3000740).wrl' \
  --output public/models/celadon-stool-wrl.glb \
  --color-encoding srgb-to-linear --color-component u16
```

## 제공된 매병·향로·주전자 자료

`public/models/celadon-maebyeong-v2.glb`는 업로드한 `청자매병-실물질감-v2.glb`를 그대로 복사한 약 20MB 파일입니다. 4K 기본 색상, 2K 법선·거칠기 이미지와 PBR 재질을 유지하며 참고 녹색을 덧입히지 않습니다. 파일 설명에는 사진 참고 재현이며 보이지 않는 면은 근사했고 실측 스캔이 아니라고 명시되어 있어 관찰·촬영 출처에도 이를 표시합니다. 제공 모델의 출처 링크는 `https://firefoxcat.booth.pm/items/6118090`입니다.

`public/models/celadon-incense.glb`는 제공 PLY의 두 부분 `duk002990-001-30000_step3.ply`, `duk002990-002-30000_step3.ply`에서 만들었습니다. 원본 정점 총 246,512개·삼각형 총 491,623개이며, 상대 위치를 유지하고 면 수를 약 28%로 줄인 약 3.3MB 파일입니다. 원본 RGB가 대부분 흰색이므로 화면의 청자색은 참고 표현입니다. 원본 색상으로 전환할 수 있고 촬영에도 표시 방식을 기록합니다. [소장품 설명](https://www.museum.go.kr/MUSEUM/contents/M0201020000.do?relicId=1227&schM=search)과 제공 3D 데이터의 출처는 구분합니다.

```sh
blender -b --python scripts/convert_model.py -- /path/to/extracted-ply-files
```

`public/models/celadon-ewer.glb`는 제공 `gae000002-000-30000.zip`의 두 OBJ와 MTL·JPEG를 사용한 약 10.1MB 파일입니다. **298,240개 삼각형과 두 부분의 공유 좌표·UV를 유지**하고 원본 8K 사진 두 장을 웹용 4K JPEG로 줄였습니다. MTL의 누락된 첫 글자 경로를 실제 같은 부분의 JPEG에 연결했으며, PLY·STL 형상을 섞거나 참고색을 덧입히지 않습니다. 변환 정보는 `public/models/celadon-ewer-source.json`, [소장품 출처](https://www.museum.go.kr/MUSEUM/contents/M0504000000.do?relicId=858&schM=view)는 별도로 표시합니다.

## 베개 · 사진 기반 3D 재현과 원본 사진

제공 `청자베개-기본화질개선.swf`는 실측 3D 메시가 아니라 다각도 사진 자료입니다. 정적으로 분석해 추출한 **54장 JPEG**를 `public/models/celadon-pillow/A01.jpg`~`F09.jpg`에 보관합니다. 각 사진은 1535×1183이며, 다시 인코딩하지 않아 SWF 내부 JPEG 바이트와 SHA-256이 같습니다. SWF와 ActionScript는 배포하지 않습니다.

기본 ‘3D 재현’ 모드에서는 사진의 공통 특징과 촬영 위치를 추정해 만든 형상을 회전·확대합니다. 보이지 않거나 불안정한 부분의 형상은 근사·보정했으며 실측 스캔이 아닙니다. 밑면에는 원본 F01을 별도로 투영하고, 밑면을 가리는 받침대를 두지 않습니다. [복원 안내](scripts/PILLOW_RECONSTRUCTION.md)와 `public/models/celadon-pillow-reconstruction-source.json`에 과정을 기록합니다.

**원본 사진 54장**으로 전환하면 확대 전 드래그로 시점을 바꾸고, 확대 후 드래그로 사진을 움직입니다. 휠·두 손가락·확대 버튼을 지원하며 방향키, +/-, Home도 사용할 수 있습니다. 촬영은 선택한 모드의 실제 화면과 당시 출처를 저장합니다. 로딩 중에는 촬영을 막고 3D를 열지 못하면 원본 사진 모드로 안내합니다.

맵의 `public/art/previews/celadon-pillow-cutout.png`는 원본 C05 사진의 배경을 제거한 **맵 전용 미리보기**입니다. 보고서 사진으로 대신 사용하지 않습니다. [국립중앙박물관 원본 뷰어](https://www.museum.go.kr/relic3D/3D/2-duk000375-000-01.html)는 출처 확인 링크입니다.

## GitHub → Vercel

대상 저장소는 `BAEPPY/minichungjamuseum`입니다.

1. GitHub에 프로젝트를 업로드합니다. `node_modules`, `dist`, `.env`, `.vercel`은 제외합니다.
2. [Vercel New Project](https://vercel.com/new)에서 저장소를 Import합니다.
3. Framework는 **Vite**, Root Directory는 저장소 루트, Node.js는 **24.x**를 권장합니다.
4. Install `npm ci`, Build `npm run build`, Output `dist`를 사용합니다.
5. `vercel.json`에 빌드 설정이 있으며, Git 연결 후 브랜치 push마다 배포할 수 있습니다.

기본 개인 체험에는 환경변수가 필요 없습니다. `api/reports.js`는 Vercel 서버리스 함수입니다. Vite만 실행하면 API가 실행되지 않아 로컬 모드로 동작합니다. 로컬 API 실행이 필요하면 Vercel CLI로 프로젝트를 연결한 뒤 `vercel env pull .env.local`, `vercel dev`를 사용합니다.

## 다른 기기와 보고서 공유

1. Vercel Marketplace에서 **Upstash Redis**를 연결합니다.
2. 자동 등록된 `KV_REST_API_URL` + `KV_REST_API_TOKEN` 또는 직접 설정한 `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN`을 사용합니다. 둘 다 있으면 완전한 `UPSTASH_*` 조합을 우선하며 서로 다른 조합의 주소·토큰을 섞지 않습니다. 환경변수 변경 후 재배포합니다. `VITE_`를 붙이거나 토큰을 코드·GitHub에 저장하지 않습니다. `KV_REST_API_READ_ONLY_TOKEN`과 `REDIS_URL`은 이 연결에 사용하지 않습니다.
3. 교사가 영문·숫자·하이픈 **12~48자**의 전시실 코드를 배포하고, 학생들은 설정에서 같은 코드를 입력합니다.
4. 이후 게시하는 통합 보고서가 공유됩니다. 기존 로컬 보고서를 자동 업로드하지 않습니다.
5. 야외 전시대에서 새로고침·다음 전시판으로 읽습니다. 목록은 최대 200개, 보고서는 30일 후 만료됩니다. 필요한 자료는 인쇄/PDF 또는 로컬 보고서 JSON 내보내기로 보관합니다.

첫 3점의 관찰·생각·근거와 이후 5점의 특징은 `report.course`에 함께 저장하며 공유 API가 길이·항목을 검증합니다. 이 필드가 없는 이전 보고서도 읽고 공유할 수 있습니다. 최종 보고서는 관찰 사진 1~3장과 이름·제목 등을 포함하며, 공유 전송 크기 제한은 사진 압축과 함께 적용합니다.

이 코스는 접근 코드를 공유하는 개인 탐험 시제품입니다. 다른 친구의 아바타·음성·채팅은 실시간으로 보이지 않습니다. 학생별 로그인·교사 승인·게시물 삭제 관리 기능은 포함하지 않습니다. 전시실 코드를 아는 사람은 같은 방의 보고서를 읽고 게시할 수 있습니다.


브라우저 검사는 기본 `/usr/bin/chromium`을 사용하며 다른 경로는 `CHROMIUM_PATH`로 지정합니다. 단위 검사는 비교 완료 조건·독립적인 5점 특징·통합 보고서와 공유 API의 새 필드/이전 보고서 호환을 다룹니다. E2E는 닉네임·최소 꾸미기, 비교 단계 잠금과 준비/오류 처리, 사진·메모 저장, 실제 기본 모델의 관찰·촬영, 등록 파일 교체·복원, 보고서·전시, 위치 복원과 모바일 조작을 검사합니다.

실제 3점 + 5점 전체 동선 검사는 일본 매병의 공식 원본 사진과 나머지 기본 모델을 사용합니다. 독립적인 관찰·저장 테스트에서 쓰는 명시적인 시험 데이터와 배포 작품을 구분합니다. 실제 Upstash 연결은 환경변수 설정 후 별도로 확인해야 합니다.
